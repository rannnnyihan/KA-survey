# 主库数据结构（Master JSON Schema）

主库是整个证据库的唯一事实源。评分脚本（rescore）读它 → 写回分数字段；HTML 生成器（gen）读它 → 产出交付物。所有迭代操作（合并CSV、补证据、清洗链接）都直接改它，改前必须备份。

## 文件命名

- 主库：`{地区}70行业指标证据_数据_{YYYY-MM-DD}.json`（如 `北京70行业指标证据_数据_2026-09-03.json`）
- 中间镜像：`{WORKDIR}/evidence_recs.json`（评分脚本同步写出，HTML 生成器从这里读）
- 宏观指数：`{WORKDIR}/macro_indices.json`（可选）

## 顶层结构

JSON 数组，每个元素一个行业记录（record）：

```json
{
  "code": "39",                     // GB/T 4754 国民经济行业分类大类代码（字符串！）
  "name": "计算机、通信和其他电子设备制造业",
  "position": "……",                 // 客观事实：该行业在本地的形态/载体企业/背景
  "reason": "……",                   // 子代理早期主观判断（仅供对照，不参与排名）
  "cred": "高",                      // 证据可信度（高/中/低，一句话理由）
  "agent_rating": "信号中强",        // 早期主观评级（rescore 后保留作对照）
  "agent_dimscores": {…},           // 早期主观维度分（对照用）

  "cells": [ … ],                   // 证据格数组（见下）

  // —— 以下字段由 rescore_evidence.py 计算写入，勿手改 ——
  "dimscores":   {"需求增长": 4.27, "供给能力": 4.56, …},   // 1–5 原始分，键=完整维度名
  "dim_weighted": {"需求增长": 21.35, …},                    // 加权贡献分 = 原始分/5×权重
  "dim_signals": {"需求增长": {"pos": 16, "neg": 0, "neu": 2}, …},
  "dim_notes":   {"盈利质量": "单向弱正"},                    // 权衡标注（可缺省）
  "flags":       ["盈利质量：正向信号票数≤2…"],              // 页面"信号权衡标注"
  "score100": 87.23,                                          // 综合信号分
  "rating": "信号强",                                          // 分级（80/65/50/35 分档）
  "rank": 1,                                                  // 全榜排名
  "core_filled": 17,                                          // 核心19格已填数
  "filled": 22, "missing": 3,
  "dims_available": 6, "na_filled": 0
}
```

**维度命名双轨制（易错点）**：`dimscores` 等分数字段用**完整维度名**（"需求增长"），`cells[].dim` 用**2字名**（"需求"）。两套名字靠 `DIM_CELL` 映射互转，改任何一处都要同步另一处。还有第 7 个 `dim: "补充"`（生态补充信号，展示但不参与六维评分）。

## 证据格（cell）结构

```json
{
  "dim": "需求",                    // 2字维度名，或"补充"
  "ind": "市场需求增长",            // 指标名（见下方19个核心指标）
  "ev": "2026H1上海集成电路产业销售收入增长15.6%，……",   // 证据文本（数字/事实）
  "year": "2026上半年",             // 口径时段
  "tier": "S1",                     // 来源层级 S1官方→S4转载
  "urls": ["https://…"],            // 来源链接（具体文章页，禁止官网首页占位）
  "miss": false,                    // true=缺本地数据占位格（ev 写原因）
  "national": true,                 // 可选：全国口径数据（评分中性化，不计正负）
  "hist": [                          // 可选：被替换的历史证据留档
    {"ev": "…", "year": "2025", "tier": "S3", "urls": ["…"]}
  ]
}
```

## 19 个核心指标（六维 × 指标）

| 维度(2字) | 指标 |
|---|---|
| 需求 | 市场需求增长、出口增长、下游行业景气度、渗透率提升空间、客户预算增长 |
| 供给 | 工业增加值、供给瓶颈、行业集中度、产能利用率 |
| 盈利 | 龙头企业收入增长、利润率改善、ROE/ROIC |
| 资本 | 行业投资增长、融资活动增长 |
| 技术 | 技术突破、商业化成熟度 |
| 政策 | 政策提及数、政府补贴、国家战略支持 |

`core_filled` 只统计这 19 个指标的非 miss 格。体系外新指标（如"火箭星城""母基金"）作为额外格追加，HTML 中归入"其他沪上信号"区展示。

## 宏观指数文件（macro_indices.json）

```json
[{"title": "制造业PMI", "text": "2026年7月制造业PMI为50.4%…", "year": "2026-07", "tier": "S1", "urls": ["…"]}]
```

生成器内 `_macro_targets()` 按标题关键词映射到行业代码组（制造业 PMI→13-43、EPMI→装备+信息、FAI 按文本细分等）。无对应行业的全市/全国总量条目返回 `[]` 直接丢弃。宏观条目仅作"对照展示"，不参与评分。

## 待合并 CSV 格式（merge_evidence_csv.py 输入）

12 列，UTF-8-BOM：

```
排名, 代码, 行业名称, 分数, 维度, 指标, 状态, 年份, 层级, 证据, 链接数, 链接(；分隔)
```

- 状态三档：`有上海口径或上海主体证据` / `上海细分未直接披露/全国或代理` / `未明确上海口径`（新地区按 adapt_region.sh 替换后的措辞）
- 证据列若为 `文本｜备注` 复合形式，取 `｜` 前部分
- 合并四规则 R1–R4 见 methodology.md
